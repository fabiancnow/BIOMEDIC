# Supabase Postgres Best Practices — BIOMEDIC Centro Médico (Cuenca)

## Reglas de Base de Datos, Auth y Seguridad LOPDP (`public.leads`)

1. **Estructura Obligatoria de la Tabla `public.leads`:**
   - `id`: `bigint generated by default as identity primary key`
   - `created_at`: `timestamptz not null default now()`
   - `nombre_completo`: `text not null`
   - `correo_electronico`: `text not null`
   - `whatsapp`: `text not null`
   - `empresa_negocio`: `text not null`
   - `presupuesto_estimado`: `text not null`
   - `dolor_principal`: `text not null`
2. **Row Level Security (RLS) y Protección LOPDP:**
   - RLS activo en `public.leads` con políticas controladas para inserción desde la Landing Page y consulta segura.
   - Enmascaramiento automático de PII (teléfono y correo) en la interfaz cuando no existe una sesión médica/administrativa autenticada en Supabase Auth.
3. **Manejo Seguro de Variables de Entorno:**
   - Usar exclusivamente `NEXT_PUBLIC_SUPABASE_URL` y `NEXT_PUBLIC_SUPABASE_ANON_KEY` en el cliente; jamás exponer `service_role`.
